# Kimi K3.1 Pro预发布版技术调研

---

## 0. 摘要

月之暗面 10 月 24 日发布的 **Kimi K3.1 Pro**。最关键的几点说在前面：

- **这不是一次新架构发布，而是一次后训练升级。** 它基于今年 7 月发布的 Kimi K3 同款 MoE 骨架，没有重新预训练，靠加大强化学习算力、把 RL 覆盖到数百个下游领域才把能力拉上来 [1]。
- **能力已经摸到闭源第一梯队。** 在智能体编程、长程 SWE、带工具末考、3D/CAD 建模、金融文档分析这些方向上，它和 Claude Opus 5.5、GPT-6 Astra 同梯队，部分还反超。
- **性价比继续走高。** API 单价较上一代 K3 整体下调约三分之一，同时它是目前参数规模最大的、计划开放权重的旗舰模型。
- **短板也很清楚。** 科学计算类终端任务、计算机使用、部分长程代码基准仍落后于头部闭源模型。

**为什么是这个时间点发布？** 

自 Kimi K3（7 月）之后三个多月没推同规模旗舰，而这段时间 OpenAI（GPT-6 Astra / Sol）、Anthropic（Opus 5.5 / Sonnet 5.5）密集更新。K3.1 Pro 没有去拼通用对话，而是选了**长链路 Agent + 专业工具调用（3D/CAD/金融）**这条差异化路线反击，同时把价格砍掉约三分之一，延续"开放权重 + 高性价比"追赶闭源前沿的策略。

## 2. 核心架构与创新点

需要强调：**架构层面沿用了 K3，本次没有新骨架。下面 2.1–2.4 都是继承自 K3 的能力，2.5 才是这次训练/推理层面的变化。**

> 原文是这样说的：
>
>  ”**Kimi K3.1 Pro 是**[ **Kimi K3** ](https://mp.weixin.qq.com/s?__biz=MzcwMjM3ODEzOA==&mid=2247487373&idx=1&sn=89bc05784771bba3f8f680e630bfcdd6&scene=21#wechat_redirect)**的后训练版本，后训练算力大幅增加。**为了支撑**数百个下游领域**的大规模联合训练，我们优化了技术栈的每一层，包括 RL 框架、长上下文推理、训练效率、沙箱基础设施、调度系统，以及用于环境质量检查的共享平台等，确保每一份新增的 RL 算力都能转化为稳定、高效的回报。最终，Kimi K3.1 Pro 模型在所有领域都获得了大规模 RL 带来的全面提升。
>
> **在代码、Agent 和知识类基准上，K3.1 Pro 达到或接近最强闭源模型的水平。Terminal-Bench 4.0** 通过真实环境中资源受限的终端任务考察编程智能体的能力，每项任务均设有严格的专项测试。K3.1 Pro 在此项评估中得分 65.7%，超过 GPT-6 Astra（58.2%），与 Claude Opus 5.5（66.4%）仅有微弱差距。**Kimi** **Code Bench** **3.0 Long-horizon** 是我们内部的基准测试，覆盖多种工程领域，重点考察编程智能体的多步执行、工具调用和端到端问题解决能力。K3.1 Pro 在这项测试中得分 61.2%，高于 K3 的 55.95%。“

### 2.1 稀疏 MoE 架构（继承 K3）

- 总参数 **2.8 万亿（2.8T）**，含 **896 个专家网络**，每次前向仅路由激活 **16 个专家**，单次激活约 **1040 亿（104B）** 参数，激活占比约 **3.7%** [1][2]。
- 我的理解：它把"全参规模"和"实际算力开销"在运行时解耦开来，这是推理成本可控、也敢于做开放权重的根本前提。

### 2.2 Kimi Delta Attention（基于 Gated DeltaNet）
- 这是一种**自定义显存节省技术**，基于 **Gated DeltaNet**，用来降低解析用户提示时的显存占用 [1]。
- 我的理解：1M 长上下文下，标准注意力的 KV 缓存是显存杀手；这类门控记忆机制直接缓解长上下文推理的 KV 膨胀，也是"长上下文不显著加价"的工程支撑之一。具体实现和收益，等权重开放后值得实测验证。

### 2.3 1M 原生长上下文（继承 K3）
- 1,048,576 tokens 原生窗口，可直接吞入大代码仓库、完整招股书、多章技术文档、长 Agent 执行轨迹，无需激进预切分。

### 2.4 多模态输入（继承 K3）
- 接受文本 / 图像 / 视频三类输入，输出文本；3D、动画、游戏等视觉产物由模型**编写并运行外部专业软件脚本**（Blender、FreeCAD、Unity、Unreal、Godot 等）生成，而非模型直接出图。

### 2.5 训练与可控推理
- **预训练**：沿用 K3 基座，**未重新预训练**。
- **后训练**：大幅加大 RL 算力投入，RL 框架、长上下文推理、训练效率、沙箱基础设施、调度系统、质量检查平台各层都做了优化，支撑数百个下游领域的大规模联合训练 [1]。
- **可控推理**：**始终开启思考模式**，推理强度 `reasoning_effort` 可在 **low / high / max** 三档间配置（默认 max）。简单检索/分类走 low 省成本，复杂编程/数学/金融建模走 high/max 深挖。但要注意，**reasoning token 按输出单价计费**，max 档长 trace 可能主导账单。

## 3. 后训练更新

- **核心改动**：在 K3 骨架上做大规模后训练强化（非预训练），RL 覆盖数百下游领域；重点补强长程编程、3D/CAD 工具调用、金融研报端到端、事实准确性。
- **性质判断**：明确的**定向强化（后训练 checkpoint 升级）**，不是新基座。
- **一处重要的安全取舍**：为准备开放权重，官方在中期训练与 RL 两阶段识别并移除了网络攻防相关数据，使漏洞利用基准通过率由 **90.5% 降至 81.0%**——也就是有意削弱攻击性安全能力，且仍落后于前沿闭源 [1]。这点做安全评估时要心里有数。

## 4. 性能对比

> 以下所有结果均基于 max 思考档。

### 4.1 纵向对比（K3 → K3.1 Pro）

综合指标对比

| 指标 | Kimi K3 | **Kimi K3.1 Pro** | 变化 |
|---|---|---|---|
| Kimi Hallu Bench Hard（事实陈述错误率，越低越好） | 23.4% | **8.3%** | −15.1% |
| Kimi Code Bench 3.0 长链路 | 55.95% | **61.2%** | +5.25% |
| API 输入（未命中缓存，¥/M） | 20 | **13** | −35% |
| API 输出（¥/M） | 100 | **68** | −32% |
| API 缓存命中（¥/M） | 2 | **1.3** | −35% |

纵向看，事实性、长程代码都有实打实的提升，单价全线下调约三分之一。

## 5. 成本、定价与部署要点

### 5.1 定价（标准版，与 K3 对比）

![image-20261026211212240](Kimi%20K3.1%20Pro%20%E6%8A%80%E6%9C%AF%E8%B0%83%E7%A0%94%E6%8A%A5%E5%91%8A.assets/image-20261026211212240.png)

- 国内开放平台以人民币计价，海外以美元（$2 / $10）计价 。
- **高速版 Highspeed**：同智能水平，输出速度约 **2–3×**，价格 **2×**（即 $4 / $20，缓存读仍为 $0.20）。
- **无分时计价**，定价跨上下文长度统一扁平（无长上下文加价）。
- 缓存默认 TTL 5 分钟；官方支持流式输出、结构化输出、工具调用、动态加载工具、TTL 上下文缓存，且**兼容 OpenAI SDK**。

### 5.2 部署成本杠杆
![Terminal-Bench 4.0 得分与单任务成本对比](Kimi%20K3.1%20Pro%20%E6%8A%80%E6%9C%AF%E8%B0%83%E7%A0%94%E6%8A%A5%E5%91%8A.assets/terminal-bench-pareto.jpeg)

- 真正该看的是**"每完成一个任务"的成本**，不是每 token 单价。K3.1 Pro 因为 reasoning token 计入输出、max 档长 trace 消耗大，单任务 token 量可能反而上升，但单价下调抵消后整体更划算。
- 官方给的测算示例：10 万未缓存输入（$0.20）+ 1 万输出（$0.10）= **$0.30**（不含 cache write / 工具循环 / 重试）。

### 5.3 开放权重与自托管
- 完整模型权重计划 **2026-11-04 前发布**（经网络安全筛查的开源版本）。
- 企业版默认关闭需手动开启；API 客户可用**零数据留存**选项。

## 6. 技术趋势洞察（算力视角）

1. **推理瓶颈从"算力"转向"显存/带宽 + KV 压缩"**：1M 上下文 + 始终思考，KV 缓存与长 trace 显存成为主要矛盾；Kimi Delta Attention（Gated DeltaNet 类）这条线性/门控记忆路线值得跟踪其开源实现。
2. **MoE 小激活调度是性价比主战场**：896 专家 / 16 激活、激活仅 3.7%，证明"大总参 + 小激活"仍是追赶闭源的成本最优解；部署重点是专家路由与激活调度的工程优化。
3. **"开放权重 + 高性价比"成为国产旗舰标准打法**：K3.1 Pro 延续该路线，把开源模型的能力天花板又往上推了一截。
4. **后训练（RL）取代预训练成为能力增量主源**：K3→K3.1 Pro 零预训练、纯后训练 + 数百领域 RL，说明能力上限越来越由后训练数据/算力工程决定。
5. **可控推理预算（reasoning_effort）成为标配**：low/max 分级把"算力-成本"开关交还开发者，但计费耦合 reasoning token，需要配套成本治理。
6. **Agent 工具链一体化交付**：模型直接驱动 Blender / UE / Godot / FreeCAD，产物链延伸到外部软件执行——推理服务需与沙箱、工具网关、外部运行时一体化设计。
7. **安全对齐与开放权重的张力显性化**：为开源主动削弱漏洞利用能力，提示"开放权重模型"在安全与能力间的取舍是长期议题。

## 7. 适用场景与局限

**最适合：**
- 长链路编程 / Agent（Terminal-Bench、SWE-Marathon 同梯队）
- 3D / CAD 参数化建模（BenchCAD 92.7%，配合 Blender / FreeCAD / 游戏引擎）
- 金融研报端到端（检索 → 跨文档核对 → 财务建模 → 盈利分析）
- 长文档 / 大代码库理解（1M 上下文）
- 成本敏感的专业批量任务

**局限与风险：**
- **科学计算终端任务短板**：Science 0.1 仅 38.1%，科学计算 Agent 暂不适用。
- **计算机使用（OSWorld）略落后** 头部闭源模型。
- **长程代码基准仍有 gap**：Kimi Code Bench 3.0 长链路 61.2% 落后 Astra 66.5%。
- **长上下文检索需自测**：1M 窗口 ≠ 长文档检索可靠，生产前须回归验证。
- **始终思考 + reasoning 计费**：max 档长 trace 成本不可低估，需配 reasoning_effort 治理。
- **权重尚未开放**：暂无可用 checkpoint，自托管计划 11-04 前；开放后实际表现建议内部实测再下选型结论。

## 8. 启发

1. **显存/带宽优先于峰值算力**：评估推理集群时，把 1M 上下文 + 始终思考的 KV/显存占用作为头号指标；跟踪 Kimi Delta Attention（Gated DeltaNet 类）开源实现，看能否复用到我们的长上下文推理。
2. **MoE 小激活调度工程化**：896 专家/16 激活的路由与激活调度是性价比关键，可对照我们自研 MoE 的路由策略与专家并行粒度做 benchmark。
3. **自托管可行性研判**：2.8T 权重开放后，先测算实际部署所需卡数/显存/互联带宽；明确"开放权重 ≠ 轻量自部署"，建议先做最小可用推理验证再决策。
4. **成本治理机制**：接入 API 时强制设 reasoning_effort 上限、默认 cache TTL 与 prefix 复用策略；把"每任务成本"而非"每 token 单价"纳入选型 KPI。
5. **Agent 工具链一体化**：若做专业场景 Agent，需把 Blender/UE/FreeCAD 等外部运行时 + 沙箱 + 工具网关纳入交付，而非仅接模型 API。
6. **后训练能力迁移**：复盘 K3→K3.1 Pro 的"零预训练 + 数百领域 RL"路径，对我们内部后训练数据管线（合成数据、领域覆盖、质量检查平台）是否有可借鉴项，值得开个专题讨论。
7. **竞品对标基线**：把 K3.1 Pro 作为"国产开放权重天花板"基准，横向对齐 GPT-6 Astra / Opus 5.5 的短板维度（科学计算、计算机使用），明确我们自研模型的差异化机会。
